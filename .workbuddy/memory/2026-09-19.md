## 修复「无法获取当前页面」（20:59）
- 根因：popup.js 用 `await chrome.tabs.query(...)` 的 Promise 风格，但 MV2/Firefox 下 chrome 命名空间不返回 Promise → tabs 为 undefined → 抛异常 → 返回 null → 显示「无法获取当前页面」
- 修复：
  - popup.js 的 getCurrentTabUrl 改为回调风格（Chrome/Firefox 均支持），并兼容「返回 Promise」的实现
  - sendMessage 改为回调风格（MV2 下 chrome.runtime.sendMessage 不返回 Promise，是下一个必踩的坑）
  - background.js 的 onActivated 改回调风格
  - 新增兜底：background 跟踪 activeTabId/activeTabUrl，popup 直接 query 失败时发 GET_ACTIVE_TAB 消息取 URL
- 经验：MV2/Firefox 下 chrome.* API 一律用回调风格（或判断返回是否 thenable 再兜底），别用 await 直接调

## WHOIS 改用天行数据 TianAPI（21:38）
- 主数据源改为天行 `https://apis.tianapi.com/whois/index?key=cb3e5ac6c0c94733bb638aeb09bae351&domain=xxx`，RDAP 兜底
- 天行返回字段：result.creation_date / expiration_date / registrar / registrant / email / phone / status / dns_server
- 坑：天行实际日期格式是 `"2000-09-28 00:00:00"`（空格分隔、北京时间、无时区），文档示例却是 `"2016-06-28 T08:48:10Z"`。normalizeDate 统一提取日期部分、按 UTC 零点处理，避免时区偏移
- 坑：天行对部分域名（如 ishuitunapp.com）返回 `code:250 数据返回为空`
- 关键发现：verisign 的 .com RDAP 是「瘦数据」——只有 status + 注册商 handle + nameservers，**无注册/到期日期**（这是之前 .com 域名显示「未知」的根因）。完整数据在注册商 RDAP（response.links 里 rel=related 指向如 rdap.dnspod.cn）
- 修复：queryWhoisRdap 增加「跟随 related 链接」逻辑——主响应无 events 时跳到注册商 RDAP 拿完整数据。dnspod 等注册商 RDAP 带 `Access-Control-Allow-Origin: *`，无需额外 host 权限
- 实测：people.com.cn 天行有数据；ishuitunapp.com 天行空、走 RDAP related 跟随拿到注册 2026-01-31 / 到期 2027-01-31 / DNSPod
